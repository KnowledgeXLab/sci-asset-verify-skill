# 注册表规则

逐列的真实填写样例、长度基准、按资产类型的差异和常见错误见 [registration-examples.md](registration-examples.md)。

## 模板与字段

用 openpyxl 读取原始表头、字段说明、可选词表和注册规则。以普通模式、`data_only=False` 保存副本，保留工作表、公式、样式、数据验证及链接；原模板保持不变。按实际表头映射字段，更新同编号行或追加新资产，保留无关历史行。

检查模板完整性；说明页与明细列数不一致时，以实际表头为写入目标。read_only 模式维度可能缺失，按实际迭代行读取。

## 表述口径

整行使用一致的资产名称、功能、输入输出及版本口径；摘要、依赖、环境、质量和验收条件的详略与前面的已填内容对齐。默认每格用一句话或少量短语，必要时补充关键数值、单位或版本。

表内直接说明资产能力、必要条件和验证结果。质量说明概括质量表现与关键结果；评价指标与验收条件概括主要指标和通过标准。详细 case 清单、执行命令、完整依赖、容差推导、逐字段误差和来源定位保存在用例明细及证据文件中。

仅做登记时，使用匹配当前资产和版本的已有报告作为结果依据，直接概括报告结论，不必在表内交代报告随包提供或本次填表是否重新运行。报告路径、验证日期、版本和来源写入 field-evidence.json；执行状态在 state.json 中如实记录。用户要求新运行时，以新运行结果更新表格。

只在实际问题影响使用或验收结论时简短说明问题，不添加泛化的防御性声明。报告没有支持的数值或结论不补写；缺少信息用简短的“待补”“未验证”或“不适用”标记，具体原因留在证据文件。

## 一资产一行

本次范围内每个独立资产在“资产明细”有且仅有一行。生成 `registration/asset-row-map.json`，记录 asset_id、version、来源目录、sheet、row、case_ids、登记状态；核对 inventory 与本次行映射的资产集合完全相等。

权重、配置、文档和数据分片作为资产组成文件；独立数据集、模型、工具、skill 分别登记。复用已有登记粒度，拆分套件时记录父子关系与编号映射。重复副本共用一行并记录来源；不同版本同时登记时使用唯一版本化标识，保留原 ID。

多个 case 不增加资产行。case_ids 保存在行映射及用例明细中，资产行只填验收标准、结果摘要，报告链接按需填写。缺用例、真值或运行条件也须登记；有适用的已有报告时按报告填结果，无验证依据时标为未验证。历史范围行不计入本次统计。

## 28 个资产字段（表头共 29 列，另有“记录人”）

以下列号用于说明字段顺序，实际按表头匹配；表头在 AA 之后还有“记录人”一列，备注位于 AC。各字段来源记录在 field-evidence.json。

| 列 | 字段 | 填写要求 |
|---|---|---|
| A | 资产编号 | 复用已有唯一 ID；新增编号按模板规则分配并查重，编号映射存证据文件 |
| B | 资产名称 | 科学对象、功能与必要规格组成的简明名称 |
| C | 资产类型 | 从 data/tool/model/environment/skill/task/trajectory/benchmark 中选择 |
| D | 领域Profile | 按模板领域词表填写；模板用 `domain:*`，部分已交付清单用中文领域名，更新旧行时沿用原值 |
| E | 资产摘要 | 一两句话说明内容、用途及核心能力 |
| F | 任务∣操作标签 | 按模板标签词表填写 |
| G | 任务描述 | 简述给定条件、处理目标和产出 |
| H | 科学对象 | 实际处理的科学实体 |
| I | 项目负责人 | 交付材料或用户提供的负责人及组织 |
| J | 提供单位 | 资产实际提供方或责任单位 |
| K | 联系人 | 已提供的对接人及必要联系方式 |
| L | 来源∣产出方式 | 简述来源与形成方式，详细定位存证据文件 |
| M | 版本 | 声明的发布或 manifest 版本；未声明则据实标记 |
| N | 格式∣接口 | 主要文件格式、调用方式和必要入口 |
| O | 规模∣数量 | 核心数量或大小，并注明单位与统计口径 |
| P | 时间范围 | 已提供的采集、实验或快照时间 |
| Q | 空间∣坐标∣实验条件 | 与任务相关的关键条件及单位 |
| R | 输入说明 | 主要输入、格式及必要单位，与任务描述一致 |
| S | 输出说明 | 主要输出、格式及必要单位，与资产能力一致 |
| T | 依赖资源 | 必需的数据、权重、工具或服务名称；完整清单及路径存使用说明 |
| U | 运行环境∣资源要求 | 主要系统或运行时、必要硬件及网络要求；仅保留影响运行的版本与资源参数 |
| V | 评价指标∣验收条件 | 先概括本次覆盖了哪几类用例与检查点（解析解、独立复算、模拟真值、非法输入、边界、规格覆盖等），再写通过标准和必要阈值；通过数量只作补充，不得只写“N/N 通过”；详细比较协议存 cases.json |
| W | 敏感级别 | 按提供方或用户确认的模板枚举填写 |
| X | 质量说明 | 一句话概括报告中的质量表现和关键结果，必要时指出影响使用的实际问题 |
| Y | 资产关联 | 关联资产 ID 及来源、派生、调用或评测关系 |
| Z | 校验 | 简明验证结论，必要时附通过数量或关键误差；与报告一致。模板若用数据验证限定为“是/空”，按模板填标记，结论放 X、用例明细或证据文件 |
| AA | 资产校验报告 | 选填。需要时填实际存在的报告相对路径或有效链接，必要时定位资产章节，公式用单个 `=HYPERLINK(...)`；留空时把报告路径或未填原因记入 field-evidence.json，不写占位链接 |
| AB | 记录人 | 填表人姓名；本列不属于 28 个资产字段 |
| AC | 备注 | 仅补充其他列未涵盖且影响使用的信息 |

表中 `∣` 对应原表头中的 ASCII 竖线，写入时保留原表头。

必填：编号、名称、类型、领域、摘要、任务标签、科学对象、提供单位、联系人、来源、敏感级别。可执行资产补充输入、输出、环境及适用接口。28 个资产字段逐项处理（记录人按需填写）；缺必填项时交付草稿并在证据文件列出缺口。链接使用单个 `=HYPERLINK(...)` 或 hyperlink 属性，修正编辑范围内的异常公式。

## case 与 Excel 的关系

在输出副本增加或更新“用例明细”，每个 case 一行，通过资产编号关联资产明细。共享用例指定主资产及关联资产检查点，覆盖统计按实际检查点归属。

## 用例明细工作表

输出副本中创建此 sheet；原始模板的资产明细仍保留 28 个资产字段（表头 29 列）。用 `用例编号` 更新已有case行；一个case多个目标字段仍为一行，逐字段比较放comparison.json。

| 列名 | 怎么填 |
|---|---|
| 用例编号 | 原始 case_id，跨包冲突时加包前缀并保留原值 |
| 资产编号 | 主资产的实际登记ID，必须存在于资产明细 |
| 关联资产及检查点 | 其他参与资产ID、版本、角色和实际检查点；无则不适用 |
| 资产版本 | 对应登记行版本及必要权重标识 |
| 用例名称 | 简述任务及检查目标 |
| 用例来源 | given/supplemental，加原始文件及位置 |
| 用例类型 | success/error/workflow/data-check/environment-check等，说明预期行为 |
| 前置条件 | 依赖、已注册MCP、设备、数据快照等 |
| 输入或Prompt | 简短原文或完整输入文件链接；文件不得缺失 |
| 执行入口 | CLI/API/MCP工具/Agent prompt入口；路径、工作目录及参数 |
| 预期结果 | 必需字段、状态、单位、产物；给定预期文件链接 |
| 真值类型 | regression/experimental/expert/historical-run/none |
| 真值来源 | 文件、样本键/行号、版本、hash；无真值说明原因 |
| 比较规则 | 对齐键、字段、单位换算、忽略项、错误语义 |
| 验收阈值及依据 | atol/rtol或任务指标阈值，以及协议来源；缺失填待确认 |
| 实际输出 | 本次actual文件链接；未运行填未执行 |
| 执行状态 | pending/running/completed/failed/blocked/skipped |
| 验证结论 | pass/fail/not_evaluated及简短原因，不能以completed代替pass |
| 误差或检查结果 | 关键误差及单位、结构/错误语义检查结果；详见comparison |
| 证据与报告 | 请求、响应、日志、comparison及报告链接 |
| 备注 | 重试、警告、限制、未覆盖项 |

cases.json 为完整机器记录，上表为可阅读索引。JSON 每例至少含 case_id、asset_id、asset_version、related_assets、source、kind、preconditions、input/prompt、entrypoint、expected、truth_kind、truth_path、comparison、threshold_source、actual_path、execution_status、validation_status、evidence。路径统一相对 run 根目录；外部原始资产需同时记录来源根目录与hash，避免搬运后误解析。


## 平台登记与完成检查

平台实体按当前 schema 构建并按引用依赖顺序提交，记录实体 ID 与回执。数据关联真实文件，模型关联权重或平台支持的服务实体，工具使用实际接口 schema；轨迹来源于真实运行，benchmark 引用所需任务、数据、环境与评测协议。平台状态与 Excel 填写状态分别记录。

完成后重载工作簿，检查表头、行数、ID 唯一性、枚举、必填、关联和链接。逐资产核对摘要、输入输出、依赖、环境、质量及验收结论的口径一致。用例编号唯一，输入、真值、实际结果和已填写的报告链接可解析；资产汇总与所引用报告一致。field-evidence.json 记录资产、字段、单元格、来源位置及状态。
