# 登记表填写示例（对外发版资产清单）

本文件回答"每个单元格写什么、写多长、什么情况下留空"，规则依据 [registration.md](registration.md)，验证结论来源 [validation.md](validation.md)。

## 样本与适用范围

- 样本一：一个数据与工具资产包（3 个 data + 19 个 tool，2026-11 验收）。
- 样本二：一份已交付的内部登记清单（`资产明细` 102 行，skill 53 / tool 24 / data 13 / model 12），用于长度基准。
- 样本二是**内部管理清单**，含资产编号/校验/资产校验报告/记录人四列；对外发版清单没有这四列，下列示例已按 24 字段改写。
- 真实内容保留，个人姓名以"负责人姓名""联系人姓名"占位。

## 填写前先定三件事

1. **表头**：直接读 skill 自带的 `assets/external-list-schema.json`（23 列），不要凭记忆、也不要抄工作区里其他 xlsx。历史版本在这里声称 28 字段/29 列 A–AC，与真实 24 字段表完全对不上；只有用户显式指定其他 schema 时才改用该 schema 并记录差异。
2. **粒度**：一个可独立登记、独立调用的资产一行。模型权重作为 model 的组成不单列；skill 内部步骤不拆行；对外的独立工具才单列。
3. **空值**：允许留空，但要有理由并记入 `field-evidence.json`。只在"选填/建议必填"字段留空；必填字段留空即交付缺口。

## 逐字段填法

| # | 字段 | 填法 | 示例（data 行 / tool 行） |
|---|---|---|---|
| 1 | 资产ID | `{project-id}/{namespace}/{asset-type}/{slug}`，即包络 asset_id 去掉 `sciasset://`；**不含版本号**，版本写「版本」列 | `2026ZD0126200/mineralmind/data/scotia` / `2026ZD0126200/mineralmind/tool/interpolate-idw` |
| 2 | 资产名称 | 科学对象+功能，≤25 字，不加书名号，不用内部代号 | `区域 A 造山型金矿数据资产` / `反距离权重插值 IDW` |
| 3 | 资产类型 | 小写枚举八选一 | `data` / `tool` |
| 4 | 领域Profile | 清单内的中文领域名（不是 `domain:*`）；对应关系写进证据文件 | `地球科学` |
| 5 | 资产摘要 | 一到两句"是什么+解决什么+边界"，19–110 字，句末"。" | `围绕区域 A 整理的金矿建模数据，含原始材料、建模输入、空间约束与既有衍生结果。` / `由训练坐标与观测值计算查询坐标处的连续标量插值。` |
| 6 | 任务\|操作标签 | 1–4 个注册词表标签，同一单元格用 `; ` 分隔，不自造前缀 | `operation:data-processing` / `operation:prediction` |
| 7 | 任务描述 | 1–2 句，30–60 字；给定条件→处理→产出 | `为研究区提供可复现的建模输入与空间约束，供证据插值、标签构建与成矿预测工具读取。` |
| 8 | 科学对象 | 顿号分隔名词短语 2–6 个，不加句号 | `地球化学样点、地质体、构造线、已知金矿点、模型栅格` |
| 9 | 资产提供单位 | 机构全称 | `示例单位（机构全称）` |
| 10 | 来源\|产出方式 | 一句"方式（说明）；详细定位见 <文件>" | `derived：由既有数据整理，来源映射见 metadata/source_mapping.json` / `derived：封装既有实现（create_dataset_from_npy），源码见 provenance.source` |
| 11 | 版本 | 语义化版本，与 `asset_version` 一致；不保留 `v` 前缀差异 | `3.1.1` |
| 12 | 格式\|接口 | 格式/接口 + 调用方式，多项用"、"或"; " | `GeoTIFF、Shapefile、NumPy NPY（文件树 + JSON 描述）` / `CLI（run_tool.py interpolate-idw --input request.json --output-dir <dir>）` |
| 13 | 规模\|数量 | 数量+单位，多项用"；"，**注明统计口径** | `484 个 payload 文件，211,656,830 字节；空间图层 131 层、变量 20 项` / `1 个 CLI 工具；输入输出 Schema 各 1 份；给定用例 9 组` |
| 14 | 时间范围 | 采集/整理时间，或"不适用（按输入重算）" | `整理快照 2026-10-13` / `不适用（每次调用按输入重算）` |
| 15 | 空间\|坐标\|实验条件 | CRS/分辨率/范围/实验条件，多项用"；" | `平台网格 114×92、1000 m（EPSG:32620 假定）；源测量坐标基准待确认` |
| 16 | 输入说明 | 字段名+格式/单位/必填性 | `包内 payload 实体（栅格/矢量/表格/NPY），逐文件声明格式、CRS、形状与摘要` / `请求 JSON 必填 arrays、coordinate_reference_system；npz 键 coords_train/y_train/coords_predict` |
| 17 | 输出说明 | 输出字段+格式/范围/单位，含失败返回 | `按角色输出数据实体（原始档案/建模输入/派生约束等）；下游由工具读取` / `interpolated_values.npy（float64，[n_query]，单位同 y_train）；失败写 error.json` |
| 18 | 依赖资源 | 一项一行或分号分隔，带版本约束；跨资产写名称 | `第三方来源 OSM(ODbL)、ESA WorldCover(CC BY 4.0)；配套工具 7 个：<工具 A>、<工具 B> 等` / `数据资产 <被依赖的数据资产名>；第三方库见 requirements.lock.txt` |
| 19 | 运行环境\|资源要求 | 系统 + 运行时 + 硬件 + 网络策略 | `Linux；Python 3.12；仅需 CPU；磁盘 ≥1.5 GB` / `Linux；Python 3.12（lock 按 3.13 验证）；仅需 CPU；输出目录须为空` |
| 20 | 评价指标\|验收条件 | 先写覆盖了哪几类检查与检查点，再写阈值与通过数（分母=已执行） | `7 组数据用例（实体属性一致性 3、共用网格 1、表格规则 2、栅格取值 1）；要求实测属性与 metadata 声明完全一致；7/7 通过` / `9 组用例（解析解 8、非法输入 1）；逐值 atol=1e-12；9/9 通过` |
| 21 | 敏感级别 | `内部`/`敏感`/`高度敏感` 三选一 | `敏感`（受限访问、限项目内非商业使用）/ `内部` |
| 22 | 质量说明 | 一句：验证通过的内容 + 限制/待确认 | `字节完整性与表征一致（SHA256SUMS 2765/2765、用例 7/7）；科学来源未全部核实，release 状态为待确认` / `用例 9/9 通过；IDW 的 search_radius 内无近邻时回退全部训练点，不是严格无支持区遮罩` |
| 23 | 资产关联 | 依赖/派生/被引用，写名称或 asset_id | `sciasset://<命名空间>/tool/<工具名> 等 7 个工具` / `sciasset://<命名空间>/data/<数据资产名>` |
## 长度基准（取自 102 行样本的中位数）

| 字段 | 中位字数 | 上限建议 |
|---|---|---|
| 资产摘要 | 42 | 110 |
| 任务描述 | 33 | 80 |
| 评价指标\|验收条件 | 21（tool 行 106） | 260 |
| 质量说明 | 37（tool 行 108） | 200 |
| 其余文本列 | 10–30 | 100 |

单元格不是报告，别把 comparison 明细、完整依赖清单、容差推导贴进来——那些放用例明细与 `field-evidence.json`。

## 可直接套用的句式

- 摘要：`<对象/数据>的<标准化/自动化处理>结果，用于<分析/训练/检索/评估>。`
- 任务描述（skill）：`根据<输入要素>，<计算/处理动作>，提供可追溯的<产出>。`
- 验收条件：`<覆盖的用例类型与检查点>（<各类数量>）；<判定标准/容差>；<通过数量/分母>。`
- 质量说明：`<验证通过的内容>；<限制/待确认项>。`
- 条件：`<CRS/设备/单位>；<限制>。`

### 验收条件不要只写"N/N 通过"

| 反例 | 正例 |
|---|---|
| `6/6 通过` | `6 组用例（解析解 4、非法输入 2）；逐值 atol=1e-12；6/6 通过` |
| `用例全部通过` | `覆盖 data/tool 两分支：data 核对声明一致性，tool 核对解析解与非法输入；123/123 通过（10 组慢用例未执行，不计入分母）` |
| `106/106 通过` | `数据用例 27/27、工具用例 96/96（skip-slow 范围）；另 10 组区域流程用例未执行，标 skipped` |

## 该清单暴露的坑（实测）

1. **按记忆硬填字段表**：历史注明"28 字段/29 列 A–AC"，内置 schema 是 24 列；照抄会多出资产编号/校验/资产校验报告/记录人四列，并漏掉"项目负责人/资产提供单位"的准确位置。**读 `assets/external-list-schema.json`，填完跑 `scripts/check_list.py`**。
2. **领域值中文 vs `domain:*`**：单元格填中文名（与选项一致），`asset.json` 里用 `domain:earth-science`；两者不要混写，对应关系记入 `field-evidence.json`。
3. **敏感级别三档**：选项只有 `内部/敏感/高度敏感`，没有"公开"；确需表达可公开时先由清单维护方扩展档位，不要自造值。
4. **版本格式混用**：`v1.0`/`1.0.1`/`v1.0.0` 并存会破坏比较与唯一性判断；统一为语义化版本（`3.1.1`）。
5. **联系人尾随空格**：样本 44 个单元格以空格结尾，筛选/关联会失配；写入用 `strip()`。
6. **分隔符不统一**：标签列用 `; `，其余多值列用"；"或"、"，同一列内不要混用。
7. **`==HYPERLINK(...)` 双等号**：正确写法是单个 `=`；写入后断言 `cell.data_type == "f"`、`value.startswith("=HYPERLINK")`、`not value.startswith("==")`。
8. **把资产协议塞进表格**：协议只写在 `asset.json` 的 `spec.asset_protocol`；表里最多在"质量说明"提一句随包提供。
9. **体量口径不清**：`file_count`/`size_bytes` 常只统计 `payload/`；写"484 个 payload 文件"而不是"484 个文件"，否则与整目录数（+5 个描述文件）对不上。
10. **通过率分母未标注**：只写"96/96"会被误读成"106 组全过"；必须写清范围与未执行项。
11. **单元格塞报告**：验收结论一句话 + 路径，明细放证据文件。

## 填后自检

- [ ] 表头与 `assets/external-list-schema.json` 逐列一致（顺序与文字）；`scripts/check_list.py` 无 error。
- [ ] 每个登记范围内的资产恰好一行，行映射与 inventory 资产集合相等。
- [ ] 资产类型/领域/标签/敏感级别取值都在词表内。
- [ ] 必填字段无空值；空值原因在 `field-evidence.json`；无校验依据的行在"质量说明"写明。
- [ ] 「评价指标|验收条件」能看出跑了哪几类用例、各自检查什么，通过率有分母与范围。
- [ ] 摘要、任务描述、输入、输出、质量说明口径一致，单位不冲突，版本一致。
- [ ] 文本已去尾随空格；链接为单个 `=` 的 HYPERLINK 或等价 hyperlink 属性。
- [ ] 重载工作簿后表头、列数、数据验证与样式未被破坏。

```
任务|操作标签        operation:data-processing
任务描述             给定训练点坐标与观测值，按反距离权重计算查询点插值，返回与查询顺序一致的数组。
科学对象             训练点坐标、观测标量场、查询点坐标

项目负责人           负责人姓名 - 示例单位

规模|数量            1 个 CLI 工具；输入输出 Schema 各 1 份；给定用例 9 组
时间范围             不适用（每次调用按输入重算）
空间|坐标|实验条件   需声明的投影坐标系（如 EPSG:32620）；坐标与观测值单位一致

```
