# 登记表填写示例（据已交付清单归纳）

本文件回答“每个单元格写什么、写多长、什么情况下留空”。规则依据见 [registration.md](registration.md)，验证结论来源见 [validation.md](validation.md)。

## 样本与适用范围

- 样本：一份已交付的内部登记清单，`资产明细` 表共 102 行。
- 类型分布：skill 53、tool 24、data 13、model 12；领域分布：地球科学 66、化学智能 30、疾病诊断 6。
- 该文件只有 `资产明细 / 字段说明 / 可选词表 / 注册规则 / 填写说明` 五个 sheet，没有“用例明细”，属于只做资产登记的旧版输出；新流程仍须按 [registration.md](registration.md) 建用例明细。
- 下文保留真实内容、数值和句式，个人姓名以“负责人姓名”“联系人姓名”“记录人姓名”占位；URL 以 `https://…` 占位。

## 填写前先定四件事

1. **编号**：`<DA|TO|MO|SK>-<批次/领域码>-<3 位流水>`，固定 10 字符，如 `DA-D01-001`。类型段必须与“资产类型”一致。同一领域可出现多个码（地球科学同时用 D05、D08），说明第二段实际按交付批次分配；新增行沿用本批次的码，不自造新码。
2. **粒度**：一个可独立登记、独立调用的资产一行。模型权重作为 model 的组成，不单列；skill 内部的多个步骤不拆行，只有对外独立可调用的工具才单列。
3. **领域写法**：该清单用中文名（化学智能/地球科学/疾病诊断），而模板 `可选词表` 要求 `domain:*`。更新既有行时保持原值；新增行按模板词表填写，并在 field-evidence.json 记录这处差异。
4. **空值**：允许留空，但要有理由。该清单的做法是：无校验的行在“备注”写“模型训练数据，无法校验”等；其余空值由源包缺失造成。原因写进 field-evidence.json，不在表内泛化补“待补”。**“资产校验报告”列可以不填**，报告路径和未填原因记入 field-evidence.json 即可。

## 逐列填法

| 列 | 本清单的填法 | 示例（截取） |
|---|---|---|
| A 资产编号 | 10 字符，类型段-批次码-三位流水；同一 ID 只能出现一次 | `DA-D01-001`、`SK-D05-007` |
| B 资产名称 | 中文，对象+功能，不超过 25 字，不加书名号 | `TLC自动化薄层色谱Rf数据集`、`岩石物理分析 Skill` |
| C 资产类型 | 小写枚举，与编号类型段一致 | `data`、`tool`、`model`、`skill` |
| D 领域Profile | 中文领域名；本表仅 3 个值 | `化学智能`、`地球科学`、`疾病诊断` |
| E 资产摘要 | 一句话说清“是什么+用于什么”，19–107 字，句末“。” | `自动化薄层色谱标准化测量数据，用于化合物结构—极性关系分析和Rf预测模型训练/评估。` |
| F 任务\|操作标签 | 1–4 个词表标签，`operation:` 在前、`stage:` 在后，用 `, ` 分隔 | `operation:data-processing, operation:analysis, operation:prediction` |

| H 科学对象 | 顿号分隔的名词短语 2–6 个，不加句号 | `有机化合物、SMILES、展开剂、Rf值` |
| I 项目负责人 | `姓名 - 单位` 或仅姓名；52/102 有值，化学包多填、地学 skill 多空 | `负责人姓名 - 厦门大学` |
| J 提供单位 | 机构全称；可写“待补充” | `浙江大学地球科学学院` |

| L 来源\|产出方式 | 一句“方式（说明）；详细定位见 <文件>”；22/102 有值，集中在自研封装批次 | `自研封装（封装项目内真实实现，暴露可移植命令行接口）；源文件与摘要见 asset_protocol_repo/source_provenance.json` |
| M 版本 | 与源包一致，保留 `v` 前缀差异，不统一格式；本表有 9 种写法 | `v1.0`、`3.1.1`、`1.0.0` |
| N 格式\|接口 | 文件格式 + 调用方式，用 `, ` 分隔；skill 多为 `markdown, Python CLI, JSON Schema` | `CSV, xlsx`、`pkl`、`CLI, JSON Schema` |
| O 规模\|数量 | “数量+单位”，多项用“；”，可含文件数、包大小 | `4,944条测量；387个化合物；3个流动相体系；17种溶剂组成` |
| P 时间范围 | 两类写法：封装/入库时间+运行方式，或“由输入数据决定”；35/102 有值 | `2026-10 封装；每次调用实时训练与计算` |
| Q 空间\|坐标\|实验条件 | CRS/单位/设备/实验条件，多项用“；”；101/102 有值 | `EPSG:4326；有序边界框，不跨反经线` |
| R 输入说明 | 字段名+格式/单位/必填性；可执行资产必填，可引用包内 readme | `TLC_ID、化合物SMILES、五种溶剂比例` |
| S 输出说明 | 输出字段+格式/范围/单位 | `实测Rf（0–1）、化合物名称/CAS及类别标签` |

| Y 资产关联 | 直接相关资产 ID，逗号分隔；19/102 有值；模型↔数据、skill↔数据/模型互指 | `MO-D01-003,MO-D01-002,MO-D01-001,MO-D01-004` |

## 按资产类型的差异

| 类型 | 填写重点 | 常见空列 | E/G/V/X 长度中位 |
|---|---|---|---|
| data | 写清数据内容、规模、字段、测量条件；R/S 必须能对上数据字典；Y 指向使用它的模型 | T/U 可空（纯数据无运行环境）、P 常空、Y 常空 | 42/31/20/37 |
| tool | V 先写用例类型与检查点、再写通过数，X 写复跑结论与限制；T 写数据依赖+第三方库；L 写自研封装出处 | Y 多为空、AC 全空 | 43/33/106/108 |
| model | 只写权重与推理入口；T/U 必填；Y 指向训练数据；X 写单模型局限 | L/P/AB/AC 全空 | 37/35/25/23 |
| skill | G 用“根据…提供可追溯…”；V 写流程约束（不得越权、不得编造）；X 写文档依据或验证结论；T 写包名清单 | I 45/53 空、L 全空、P 多空、Y 多空 | 34/54/43/33 |

## 可直接套用的句式

- 摘要：`<对象/数据>的<标准化/自动化处理>结果，用于<分析/训练/检索/评估>。`
- 任务描述（skill）：`根据<输入要素>，<计算/处理动作>，提供可追溯的<产出>。`
- 验收条件：`<覆盖的用例类型>（<各类数量>）；<检查项1>；<检查项2>；<通过数量/容差>。`
- 质量说明：`<验证通过的内容>；<限制/适用范围>。`
- 条件：`<CRS/设备/单位>；<限制>。`
- 依赖：一行一个包；工具批次用 `数据资产 <版本>（ID/ID）；第三方库 A、B、C`。

### 验收条件不要只写“N/N 通过”

只写数量看不出这份资产验证了什么，换个包也无法判断覆盖是否充分。先从 cases.json / comparison.json 归纳本次跑了哪几类用例、各自检查什么，再写数量和阈值。

| 反例 | 正例 |
|---|---|
| `6/6 通过` | `6 组用例通过（解析解 2、独立复算 1、模拟真值 1、非法输入 2）；回归判据 atol=1e-6` |
| `用例全部通过` | `覆盖 data/tool/model 三个分支：data 检查字段与主键，tool 检查 initialize/tools/list 与非法参数，model 检查权重加载与输出范围；12/12 通过` |
| `106/106 通过` | `数据用例 27/27、SHA256SUMS 全量校验、包校验通过；另做 106/106 复跑` |

写法：`<用例类型与检查点>；<判定标准/容差>；<通过数量>`。没有分类时至少写清检查对象（结构、单位、数值、错误语义、覆盖规格），不能只给一个分数。

## 该文件暴露的坑

1. **`==HYPERLINK(...)` 双等号**：96/96 个报告链接都是这种写法（openpyxl 读出的 `data_type` 为 `f`，公式以 `==` 开头，Excel 打开会报公式错误）。正确写法是单个 `=`：`=HYPERLINK("URL","报告名")`。写入后断言 `cell.data_type == "f"` 且 `cell.value.startswith("=HYPERLINK")` 且 `not cell.value.startswith("==")`。
2. **Z 列是“是否校验”标记，不是结论**：工作表数据验证 `Z2:Z102` 的列表为 `"是,,,"`，只能填“是”或空。需要写“通过 96/96”时放到 X、AA 或用例明细，不要写进 Z，否则触发验证错误。
3. **W 列验证列表缺“公开”**：数据验证为 `"内部,敏感,高度敏感"`。确需填“公开”时先调整验证范围，并在证据文件说明。
4. **领域值中文 vs 模板 `domain:*`**：模板 `可选词表` 要求 `domain:earth-science` 一类值，实际表全部用中文名。两者不要混用；更新旧行沿用旧值。
5. **编号重复**：`SK-D05-007` 被“条件资源分析 Skill”和“图表曲线数字化 Skill”两行共用。写入前必须做全表唯一性检查，重复的重新分配流水号。
6. **联系人尾随空格**：44 个联系人单元格以空格结尾（如 `联系人姓名 `）。写入时 `strip()`，否则筛选和关联会对不上。
7. **分隔符不统一**：F 列用 `, `，Y 列用 `,`（无空格）。统一为 `, ` 并保证可解析；不要在同一列混用。
8. **版本格式混用**：`v1.0` / `1.0.1` / `v1.0.0` 并存。以源包 manifest 为准，不做“规范化”改写。
9. **空值集中**：I 空 50、L 空 80、P 空 67、Y 空 83、AB 空 80。L 在模板 `字段说明` 中标注为必填，实际 80% 为空，属于交付缺口；新填时要么补齐，要么在 field-evidence.json 记为待补。
10. **无校验的写法**：6 行 Z/AA 留空，AC 备注写“模型训练数据，无法校验”“数据涉及真实用户隐私，无法进行校验”“知识库数据，无法校验”。这是可接受的降级，但不能同时把 Z 填“是”。

## 填后自检

- [ ] 编号 10 字符、全表唯一、类型段与 C 列一致。
- [ ] 每个登记范围内的资产恰好一行，行数与 inventory 的资产集合相等。
- [ ] C/D/F/W 的值在模板词表或本批次既有取值内。
- [ ] 必填列已填；空值在 field-evidence.json 有原因，无校验行在 AC 有说明。
- [ ] AA 若填写，是单个 `=` 的 HYPERLINK 公式，重载后无 `#NAME?`、无 `==`；不填时已在 field-evidence.json 记录路径或原因。
- [ ] Z 与 AA/AC 自洽：填“是”时报告路径在 AA 或 field-evidence.json 可查，留空必有备注原因。
- [ ] Y 中每个 ID 都能在资产明细或其他登记包中解析。
- [ ] 同一资产的摘要、任务描述、输入、输出、质量说明口径一致，单位不冲突。
- [ ] V 列能看出跑了哪几类用例、各自检查什么，不是只有“N/N 通过”。
- [ ] 同类行的长度与中位数相当，未把完整报告贴进单元格。
- [ ] 重载工作簿后表头、列数、数据验证、样式未被破坏，联系人等文本已去尾随空格。
